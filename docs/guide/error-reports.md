# Error reports

- Rule (product decision; the terms `terms.section.diagnostics` say the same): opt-in only, per ACCOUNT (`app_user.diagnostics_opt_in`, default false; `UserView.diagnosticsOptIn`); guests and signed-out visitors never send. Kept `glazelab.reports.retention` (30 days, promised by the terms). Linked to the account by ID only: no address, name, IP, user agent string, cookie, token, URL, query string or fragment is a column or an input field. Only site admins read them.
- Endpoints (`ReportController`; signed-in, CSRF):
  - `PUT /api/account/diagnostics` `{enabled}` → 204. Off deletes every report of the account in the same transaction and never needs the current terms; on does (428, `TermsFilter.TERMS_REQUIRED`).
  - `POST /api/reports` `ReportBatch {device, events}` → 204. Checks, in order: the body is read only up to `MAX_BATCH_BYTES` 32 KB (413 `BATCH_TOO_LARGE`; read by the controller itself, not `@RequestBody`, so the cap holds without a Content-Length; the OpenAPI body comes from `@Operation(requestBody)`); at most `MAX_EVENTS` 20 (400 `TOO_MANY_EVENTS`); bean validation (400 `INVALID_INPUT`); each event at most 4 KB as the mapper writes it (400 `EVENT_TOO_LARGE`); then 409 `ReportService.DIAGNOSTICS_OFF` for an account that has not opted in, nothing stored.
  - Device facts are typed and short (`ReportDtos.DeviceInfo`: patterns, ranges and enums), never free text.
  - An event: `kind` (`ClientReport.Kind`), `message`, optional `stack`, `count` (1–1000, default 1), `occurredAt` (more than 31 days back or a day ahead is stored as the receive time), `build` (the footer's label) and a route NAME (`[a-z][a-z0-9-]*`, never a URL).
  - The first choice comes with the activation (`diagnosticsOptIn` of the activating account link, default false; topic "Registration"), never with the registration request.
- Scrubbing (`model/ReportScrubber`, pure; vectors in `ReportScrubberTest`): the second line of defence after the app's own, on message and stack before storing.
  - Removes control characters (but newline and tab) and unpaired surrogates (PostgreSQL refuses NUL); then bearer values, the values of `name=value`/`name: value` pairs whose name contains token, password, secret, session, csrf/xsrf, authorization, api key or cookie, email addresses, query strings, fragments (every `#…`, so token hash routes) and runs of 32 or more base64url characters that are not a UUID; then truncates to the column (1000/4000, code-point safe).
  - The secret-pair and email patterns start only at a word start (lookbehind), so long input stays linear; keep new patterns linear too.
- Fingerprint (`fingerprint`: SHA-256 of kind and the scrubbed message with digit runs as 0): groups one problem across builds; computed by the server, the client sends none.
- Storage (`client_report`, `model/ClientReport`): one row per event with its batch's device columns and `received_at`; `fk_client_report_user` ON DELETE CASCADE (account deletion, a ban and the pending purge remove reports by the cascade alone; `BanApiTest.footprint` counts them); named checks for kind, occurrences and the device enums.
  - Its three indexes (`client_report_time_idx`, `client_report_user_idx`, `client_report_fingerprint_idx`) serve the purge, paging, opt-out, the cascade, the daily cap and the admins' grouping; the admin statements need no others.
  - A per-account daily cap (`glazelab.reports.daily-cap`, 500 in 24 hours) drops the rest of a batch silently (204: the app would only resend).
  - The hourly `ReportService.purge` deletes rows past the retention and logs the count only.
- Locks: `ReportService.choose` and `store` lock the actor's account row first (`CurrentUser.lockUser`) and nothing after it; the flag is read under that lock, so an opt-out or account deletion queued before a send leaves nothing and one queued after it deletes what the send stored (`ReportConcurrencyApiTest`, PostgreSQL).
- Logs never carry a message, stack or device value; validation answers name no field values either.
- Reading (`ReportAdminController` `/api/admin/error-reports`, `ReportAdminService`; site admins through `CurrentUser.siteAdmin`; writes with CSRF and terms):
  - `GET ?page&kind&build&q`: groups by `fingerprint, kind`, newest `max(received_at)` first, pages of `ImageDeletionController.PAGE_SIZE`. JPQL built from the filters that are set, bound parameters only; `q` is a case-insensitive literal contains, wildcards escaped, at most 100 characters (else 400). `message` is `max(message)` of the group. Build and browser/OS spreads are two more grouped statements over the page's fingerprints with the same filters, so counts are of the matching rows.
  - `GET /builds` (50 newest labels); `GET /{fingerprint}/occurrences?page` (`OCCURRENCE_PAGE_SIZE` 20, each with its stack and a `DeviceInfo`; a malformed or unknown fingerprint on page 0 is 404); `DELETE /{fingerprint}` and `DELETE /occurrences/{id}` are bulk deletes (404 when nothing matched; no account lock).
  - No view and no query column ever carries `user_id`: `ReportAdminApiTest` asserts the bodies hold no account ID, name or `@`; keep it so (data minimisation, product decision).
- Not synced: `UserView` is fetched in full, both writes are `EXEMPT` in `SyncCoverageApiTest`, `SyncService.FORMAT` stays.
